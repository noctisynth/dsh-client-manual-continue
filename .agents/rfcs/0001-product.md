# 手动通知续跑需求与边界

编号：RFC-001。更新：2026-11-09。依据：EVIDENCE-001、EVIDENCE-002。

## 本轮已确认事项

- 以既有调研报告及技术建议整理独立工程上下文，沿用编号导航、需求/技术方案、事实/证据与唯一待办分层的管理模式。
- 明确基本协作及 TypeScript 质量规范，技术职责与实现边界见 SPEC-001。
- 本次直接授权工程配置、TypeScript 功能实现、必要调研、本地构建与测试，以及经验证成果的约定式本地提交；原有未提交改动须保留并与本次成果区分。
- 后续用户通过明确选项授权：将本工作区插件安装并启用到当前 profile，核验真实 Loader、界面资源、原位显示及本插件禁用/卸载还原；允许必要的无模型请求 GUI 核对，可能由用户协助刷新或手动检查。授权不包含擅自修改其它插件或用户状态。
- 用户随后明确授权：收尾后使用 gh CLI 在指定 GitHub 组织下创建仓库并推送本地代码；未指定公开可见性，采用私有仓库，不强推覆盖历史。
- 仍不授权 Agent 发送真实续跑或模型请求、修改 DSH 安装文件、改审批/沙箱、实际版本更新、消费 changeset、解除包的 private 或 npm 公开发布；用户自行操作后的使用反馈不等于授权 Agent 发起额外模型请求。
- 使用 Semifold 统一管理 changeset、版本、变更日志和发布编排；不并行采用另一套版本管理工具。配置完成不等于已授权执行版本更新、推送或发布。

## 已确认产品目标

下列目标及广泛人工中断策略已由用户确认。用户已明确选择页面结构兼容的严格原位路线；授权来自本次明确选择，不从历史报告或此前倾向推导。

| 场景 | 目标行为 |
|---|---|
| 有可发送文字、附件或结构化内容 | 保留原发送行为 |
| Agent 执行中且输入为空 | 保留原停止行为 |
| 已确认异常结束或用户停止且输入为空 | 符合确认后的策略时，在同一主按钮原位置显示 ▶，点击后请求续跑 |
| 正常完成且输入为空 | 保持原界面，不自动推断工作未完成 |

插件必须可独立分发，在明确声明且实际验证过的未修改 DSH 构建上安装后开箱即用，而非仅本地可用。不包含本机路径、设备特例或特定会话绑定；支持范围以实际能力与组合验收为准，不承诺任意历史或未来版本。

无需用户手打“继续”，续跑请求不显示为普通用户气泡，而以来源明确、可展开的通知保留记录。必须如实说明它仍是模型可见的新输入、可能消耗上下文及影响缓存。严格原位不能由旁边新增按钮代替。

## 不变边界

- 只接受真实人类操作，不自动重试循环，不把手动停止变为自动重启。
- 用户进一步明确只需要继续按钮，不接受擅自增加的受理/成功状态横幅；成功续跑不得额外显示解释性提示或扩展交互。内部状态区分不等于另加用户界面功能。
- 不承诺恢复同一个模型请求、执行栈或原轮次；不保证错误重试后成功。
- 不删除历史、不由插件重放已完成工具，不扩大权限、不绕过审批，不自动激活暂停目标。
- 用户输入内容后恢复发送；连接、授权、能力或输入状态不明确时保留原界面。
- 不修改 DSH 安装文件，不将未合入的主按钮 Slot 当成已发布接口。

## 实现前待决定

1. 新增插件来源输入及原生通知语义已确认。最小正文说明：继续尚未完成工作，复用已提交结果，外部副作用结果未知时先核实；不恢复原模型流或原执行栈。
2. 严格原位优先已发布且实际可用的主按钮扩展点。当前缺失时采用用户已明确确认的页面结构兼容路线，不整体替换输入栏，不修改安装文件，不以旁边按钮代替严格原位。
3. 用户最新明确要求广泛的人工中断续跑，允许更换模型后继续，不以暂态错误允许列表限制入口。error 全部纳入（含 UNKNOWN、认证、余额等错误），明确 user 手动停止、max-tokens 和已修复且旧活动收尾的 interrupted 也可成为候选；正常完成、blocked、forked、parent/hook/disposed/legacy 取消不自行扩大为当前用户停止。后续仍须复核准确 live Agent、所有权、权限、竞争和交互，不保证重试成功，不新增错误策略配置。
4. 用户通过明确选项确认：允许在声明且实际验证过的未修改 DSH 构建上，新增原位续跑按钮并隐藏原按钮；保留正常发送/停止，结构不匹配、连接失效或卸载时还原原界面。路线可打包分发、不绑定本机，DSH 升级后重新验证。该确认只授权代码开发，不扩大安装、当前 GUI 操作或真实请求授权。
5. 用户要求正常人类点击可用，不希望参与宿主权限术语选型。技术实现采用正式 Remote 受信调用上下文，当前可证明模型执行权限的 owner 身份可接受；无 invocation 或受限调用者权限无法确认时拒绝，不添加用户权限配置，不将此写成用户已确认全面支持受限远程访客。
6. 支持范围须按实际目标契约验证；能力或权限不明确时关闭续跑，保留宿主界面。不凭版本号承诺兼容，不承诺跨崩溃全局 exactly-once。

## 后续产品验收条件

- 正常完成不出现 ▶；发送、停止、附件、引用、命令、IME 与快捷键行为不被破坏。
- 一次操作至多产生本插件可确认的一次接受；双击、多标签及旧候选不能重复投递，未知结果先对账不自动补投。
- 实际 Host 授权拒绝无权限入口；待处理审批、新输入、旧活动收尾或会话所有权变化时不能绕过检查。
- 模型确实收到预期输入，来源持久化正确，原生通知正文可展开，旧错误与工具结果保留；内部不得把接受输入等同模型开始或任务完成，不因此增加成功横幅。
- 原位位置、焦点、键盘、无障碍、多会话、重连、刷新、禁用和卸载恢复通过实际组合验证。
- 不支持构建保留宿主界面；真实安装点击闭环通过后才确认产品交付。
