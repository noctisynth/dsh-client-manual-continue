# 手动通知续跑需求与边界

编号：RFC-001。更新：2026-11-08。依据：EVIDENCE-001、EVIDENCE-002。

## 本轮已确认事项

- 以既有调研报告及技术建议整理独立工程上下文，沿用编号导航、需求/技术方案、事实/证据与唯一待办分层的管理模式。
- 明确基本协作及 TypeScript 质量规范，技术职责与实现边界见 SPEC-001。
- 当前工程工作包括上下文初始化和 Semifold 版本/发布管理配置，不包括插件功能实现、安装、实际版本更新、公开发布或对运行中 DSH 的修改。
- 使用 Semifold 统一管理 changeset、版本、变更日志和发布编排；不并行采用另一套版本管理工具。配置完成不等于已授权执行版本更新、推送或发布。

## 报告中的产品目标

以下是报告承接的产品目标，不代表报告中的每项策略和实现选项均已获实施授权。

| 场景 | 目标行为 |
|---|---|
| 有可发送文字、附件或结构化内容 | 保留原发送行为 |
| Agent 执行中且输入为空 | 保留原停止行为 |
| 已确认异常结束或用户停止且输入为空 | 符合确认后的策略时，在同一主按钮原位置显示 ▶，点击后请求续跑 |
| 正常完成且输入为空 | 保持原界面，不自动推断工作未完成 |

无需用户手打“继续”，续跑请求不显示为普通用户气泡，而以来源明确、可展开的通知保留记录。必须如实说明它仍是模型可见的新输入、可能消耗上下文及影响缓存。严格原位不能由旁边新增按钮代替。

## 不变边界

- 只接受真实人类操作，不自动重试循环，不把手动停止变为自动重启。
- 不承诺恢复同一个模型请求、执行栈或原轮次；不保证错误重试后成功。
- 不删除历史、不由插件重放已完成工具，不扩大权限、不绕过审批，不自动激活暂停目标。
- 用户输入内容后恢复发送；连接、授权、能力或输入状态不明确时保留原界面。
- 不修改 DSH 安装文件，不将未合入的主按钮 Slot 当成已发布接口。

## 实现前待决定

1. 确认接受“新增插件来源输入 + 原生通知回执”的语义取舍及续跑文案。
2. 明确原位入口路线：正式主按钮 Slot 可用时优先；否则选择整体输入栏替换，或单独接受实验性页面适配及其维护成本。
3. 确定手动停止、UNKNOWN、max-tokens、interrupted 及永久错误的策略；不得从报告示例推导默认开关。
4. 确认支持构建、权限要求和跨生产者竞争保证，不凭版本号承诺兼容或全局 exactly-once。

## 后续产品验收条件

- 正常完成不出现 ▶；发送、停止、附件、引用、命令、IME 与快捷键行为不被破坏。
- 一次操作至多产生本插件可确认的一次接受；双击、多标签及旧候选不能重复投递，未知结果先对账不自动补投。
- 实际 Host 授权拒绝无权限入口；待处理审批、新输入、旧活动收尾或会话所有权变化时不能绕过检查。
- 模型确实收到预期输入，来源持久化正确，通知正文可展开，旧错误与工具结果保留；接受、模型开始与任务完成分别呈现。
- 原位位置、焦点、键盘、无障碍、多会话、重连、刷新、禁用和卸载恢复通过实际组合验证。
- 不支持构建保留宿主界面；真实安装点击闭环通过后才确认产品交付。
