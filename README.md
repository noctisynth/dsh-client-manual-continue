# DSH Manual Continue

为 DSH 补充中断后的手动续跑入口。在任务被手动停止、运行出错或达到输出上限后，点击输入栏右侧的 **▶**，继续当前会话中的工作。

插件支持 **DSH Desktop** 和通过 **DSH CLI 启动的 Web 界面**。

## 项目背景

长任务可能因为手动停止、模型请求出错或输出达到上限而中断。已有的对话和工具结果仍在会话中，接下来需要的是让模型接着处理尚未完成的工作。

DSH 目前尚未提供内置的中断后继续按钮，通常需要用户再发送一条“继续”消息。本插件作为这一功能的补充，在原有发送／停止按钮的位置提供 **▶**，把手动输入变为一次点击。

你可以直接继续，也可以先处理报错原因或更换模型，再接着完成任务。整个过程使用当前会话，保留已有的对话、工具结果和审批设置。

## 安装

适用版本：**DSH 0.2.2-rc.1**。

在 DSH 的插件管理器中安装并启用 `dsh-client-manual-continue`，然后刷新会话页面。

已有 DSH CLI 安装的用户，也可以在终端安装并启动 Web 界面：

```sh
dsh plugin --profile web add dsh-client-manual-continue
dsh --profile web
```

## 使用

1. 打开需要继续的会话，并保持输入栏为空。
2. 点击输入栏右侧的 **▶**。
3. 任务开始执行后，按钮恢复为停止按钮。

需要切换模型时，先在会话中选择模型，再点击继续。

## 按钮行为

| 会话状态 | 按钮行为 |
|---|---|
| 输入栏中有文字、附件或引用 | 发送输入栏中的内容 |
| 任务执行中，输入栏为空 | 停止当前任务 |
| 任务被手动停止、运行出错或达到输出上限，输入栏为空 | 显示继续按钮 |
| 任务正常完成，输入栏为空 | 不显示继续按钮 |
| 插件被禁用 | 恢复 DSH 原有按钮 |

每次续跑由你点击发起。仍有待处理消息、审批或问题时，会显示对应提示。

## 续跑记录

发起续跑时，插件会向当前会话发送一条新的继续请求，并在会话中显示为可展开的通知。模型继续处理已有工作，原有对话、工具结果和审批设置保持不变。

模型继续处理时会使用会话上下文，并产生新的 token 消耗。请求状态不明确时，再次操作只核对上次请求的状态。
